# 00. 개요 — 엑셀 양식 생성·취합 도구 (KDHC-HA-Pro)

> 이 문서는 **두 개발자 모두**가 읽는 공통 문서입니다.
> - 개발자 1(생성 파트): `00-overview.md` + `01-contract.md` + `02-generator.md`
> - 개발자 2(취합 파트): `00-overview.md` + `01-contract.md` + `03-aggregator.md`
>
> LLM에게 작업을 맡길 때는 위 세 문서만 컨텍스트로 제공한다. 상대 파트 문서는 줄 필요가 없도록 작성되어 있다.

작성일: 2026-10-12 · 상태: 설계 확정(구현 전)

## 1. 배경과 목적

본사→지사, 정부→우리 기관처럼 **상위 조직이 엑셀 양식을 내려보내고, 하위 조직이 작성해 돌려주면, 담당자가 하나로 합치는(취합)** 업무가 반복된다. 현재는 다음 문제가 있다.

- 양식을 만들 때 취합을 고려하지 않아, 지사마다 칸을 바꾸거나 형식이 달라져 손으로 합쳐야 한다.
- 누가 제출했고 누가 안 했는지, 어느 파일에 오류가 있는지 일일이 확인해야 한다.

**목표: 처음부터 "취합 가능한 형태"로 양식을 만들고, 돌아온 파일을 자동으로 검증·취합한다.**

## 2. 사용자와 사용 장면

| 사용자 | 하는 일 |
|---|---|
| 운영자 (본사·본부 담당자) | 웹 화면에서 양식을 만들고, 엑셀 파일로 내보내 배포한다. 돌아온 파일을 넣어 취합한다. |
| 작성자 (지사·기관 담당자) | 받은 엑셀 파일을 **MS Excel 또는 한셀**로 열어 작성하고 돌려보낸다. 우리 프로그램을 쓰지 않는다. |

주요 장면:
1. **본사 → 지사**: 본사 인사팀이 15개 지사에 조사표를 보내고 취합한다. (주력)
2. **본사 → 본부 → 지사 (다단계)**: 본부가 지사 파일을 취합하고, 본사가 본부 취합본들을 다시 취합한다.
3. **정부 → 우리 기관**: 정부 양식을 받아 지사에 재배포한다. MVP에서는 운영자가 정부 양식과 같은 항목을 빌더로 다시 만들어 쓴다. (정부 양식을 그대로 들여오는 기능은 로드맵의 "외부 양식 표준화")

파일 전달은 **메신저·메일·공문으로 엑셀 파일 자체를 주고받는다.** 프로그램은 파일을 만들고 읽기만 한다.

## 3. 제품 형태와 기술 원칙

- **서버 없는 브라우저 웹앱.** 모든 처리는 사용자의 브라우저 안에서 끝나며, 파일 내용이 외부로 전송되지 않는다(개인정보 보호).
- 기술 스택: **React + TypeScript + Vite**, 엑셀 처리 **ExcelJS**, 압축 **JSZip**, 테스트 **Vitest**, 스타일 **Tailwind CSS**.
- 빌드 결과는 정적 파일이다. 사내 PC에서 열거나 정적 호스팅(예: GitHub Pages)으로 배포할 수 있다. (배포 방식은 미결정 — 7절)
- 지원 브라우저: 최신 Chrome, Edge.
- 제품 안에 AI 기능은 넣지 않는다. (로드맵에서 검토)

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 양식 | 운영자가 정의한 조사표. 한 양식은 **입력 시트 1개**로 구성된다. |
| 양식 정의 (`FormSchema`) | 양식의 설계도. 항목, 구조, 취합 방식, 지사 목록을 담은 데이터. |
| 블록 | 양식을 구성하는 단위. `fields`(항목:값), `list`(목록), `matrix`(고정 표) 세 종류. |
| 양식 구조 | 블록 조합. 목록형 = list, 표형 = matrix, 혼합형 = fields + list. |
| 메타 (`FileMeta`) | 생성된 엑셀 파일 안에 숨겨 넣는 설계도 사본 + 셀 위치 정보 + 지사명. |
| `_meta` 시트 | 메타가 저장되는 숨김 시트(veryHidden). 작성자에게 보이지 않는다. |
| 셀 지도 (`CellMap`) | 각 항목의 값이 엑셀의 어느 칸에 있는지 적은 표. |
| 제출본 | 작성자가 작성해 돌려준 엑셀 파일. 메타의 `kind = 'submission'`. |
| 취합본 | 취합 결과 엑셀 파일. 메타의 `kind = 'aggregate'`. 다시 취합의 입력이 될 수 있다. |
| 취합 방식 | 제출본들을 합치는 규칙. 플러그인 형태로 추가할 수 있다. |
| 지사/기관 목록 | 배포 대상 조직 목록. 있으면 지사별 파일을 따로 만든다. |
| 공통 계약 | 생성 파트와 취합 파트가 함께 지키는 약속. `src/contract/`와 `01-contract.md`. |

## 5. MVP 범위

### 5.1 포함

**양식 만들기 (생성 파트)**
- 웹 빌더에서 양식 정의, **실시간 미리보기**
- 양식 구조 3종: 목록형, 표형, 혼합형
- 항목 타입 5종: 텍스트, 숫자, 날짜, 목록 선택, 메모
- 지사/기관 식별 2방식: 목록 있음(지사별 파일 생성, zip) / 목록 없음(지사명 입력칸)
- 엑셀 입력 규칙(데이터 유효성 검사), 시트 보호, 숨김 메타, 파일 속성 이중 기록
- 양식 JSON 저장·불러오기

**취합하기 (취합 파트)**
- xlsx 여러 개 또는 zip 업로드
- 파일 식별(메타 → 파일 속성 → 양식 JSON 순), 검증, 검토 화면
- 오류 처리 정책 (아래 표)
- 취합 방식 6종, 여러 개 동시 선택:
  1. 행 이어붙이기 (`append`)
  2. 머리정보 붙여 잇기 (`header-append`)
  3. 지사별 펼치기 (`spread`)
  4. 시트 모으기 (`collect-sheets`)
  5. 취합본 다시 취합 (입력 처리 기능 — 취합본을 넣으면 지사 단위로 풀어서 다른 방식에 투입)
  6. 제출 현황표 (`submission-status`)
- 오류 목록 시트는 결과 파일에 항상 포함

**오류 처리 정책 (확정)**

| 상황 | 처리 |
|---|---|
| 값 오류 (필수칸 빈칸, 숫자칸에 글자 등) | **운영자가 파일별로 포함/제외 선택** |
| 구조 변경 (열 삭제·순서 변경) | **머리글 이름으로 맞춰서 자동 포함**, 사라진 열은 빈칸 + 경고 |
| 다른 양식 파일 | **자동 제외**하고 알림 |
| 같은 지사 중복 제출 | **최신 파일 사용**, 운영자가 다른 파일로 바꿀 수 있음 |
| 목록 밖 지사명 / 지사를 알 수 없는 파일 | **운영자가 지사 목록에서 연결** |

### 5.2 제외 (로드맵으로)
- 여러 시트에 걸친 양식
- 나머지 취합 방식 12종 (8절)
- 외부 양식 들여오기·표준화
- AI 기능
- 서버, 로그인, 제출 이력 저장

## 6. 성공 기준

1. 운영자가 개발 지식 없이 10분 안에 혼합형 양식을 만들고 15개 지사용 파일을 내려받을 수 있다.
2. 미리보기와 실제 엑셀 파일의 칸 배치가 일치한다.
3. 작성자가 MS Excel에서 작성·저장한 파일을 넣으면 수작업 없이 취합 파일이 나온다.
4. 오류 유형 5가지가 모두 검토 화면에 표시되고, 정책대로 처리된다.
5. 본부 취합본 2개를 본사가 다시 취합하면, 지사 단위 결과가 직접 취합한 결과와 같다.
6. 파일 내용이 브라우저 밖으로 전송되지 않는다(네트워크 요청 없음).

## 7. 미결정 사항 (운영자/팀 결정 필요)

| # | 항목 | 기본안 |
|---|---|---|
| D1 | 한셀·구글 시트에서 저장했을 때 숨김 메타가 유지되는지 | 0단계에서 실제 테스트 후 대응 결정 |

| D4 | 배포 방식 | 정적 파일(사내 PC) 또는 GitHub Pages |

## 8. 로드맵 (MVP 이후)

**취합 방식 추가 후보** (플러그인 구조라 파일 하나씩 추가)
- 칸별 합계, 항목별 소계, 지사별 요약, 교차표(피벗), 응답 분포, 평균·최대·최소, 순위·정렬, 키 기준 중복 제거, 기준표와 대조·병합, 전기 대비 증감, 계층 집계(지사→본부→전체), 출처 추적 열

**기능 확장**
- 외부 양식 표준화: 정부·외부 기관 양식을 들여와 우리 양식 정의로 변환
- 여러 시트짜리 양식
- 항목 타입 추가: 전화번호, 이메일, 사업자번호, 주민번호 앞자리 등
- AI 기능 검토: 자연어로 양식 초안 만들기, 외부 양식 자동 분석, 오류 값 보정 제안
