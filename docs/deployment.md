# 한난MOA 온라인 배포

## 구성

- 운영 주소: https://hanan-moa.vercel.app
- 웹·서버: Vercel `ksw1727s-projects/hanan-moa`, 함수 지역 싱가포르
- 데이터베이스: Neon `hanan-moa`, 프로젝트 `shy-pine-82314856`, 싱가포르
- 인증: Neon 관리형 인증. 사이트의 `/api/auth`에서 동일 출처 쿠키로 연결
- 인공지능: 관리자 공용 OpenAI. 한난MOA 전용 프로젝트·서비스 계정 키 사용
- 원본 회신 엑셀과 취합 결과: 기존처럼 사용자 브라우저에서 처리. 서버 저장 없음
- 사용자가 인공지능에 직접 첨부한 양식: 브라우저에서 분석한 요약만 동의를 받은 뒤 서버와 OpenAI에 전달. 원본 파일은 전달하지 않음

## 실행 모드

- 로컬 기존 모드: `.env.local`에 클라우드 설정을 넣지 않거나 `VITE_CLOUD_MODE=false`로 두고 `npm run dev`. 기존 로컬 인공지능 명령어 연결 유지
- 온라인 모드: `VITE_CLOUD_MODE=true`, `VITE_NEON_DATA_API_URL` 설정. 로그인 전에는 작업 화면에 들어갈 수 없음
- Vercel에서는 위 두 값이 없으면 빌드를 실패시켜 로컬 무인증 모드가 실수로 공개되지 않도록 함
- 서버는 `npm run build:server`로 `server/runtime.mjs`에 묶고 각 운영 함수가 이를 사용. ESM 확장자·공유 코드 경로 문제를 방지
- `npm run build`는 타입 검사 → 서버 묶음 생성 → 웹 빌드 순서

## 환경변수

브라우저 공개 설정:

- `VITE_CLOUD_MODE=true`
- `VITE_NEON_DATA_API_URL`: Neon의 HTTPS 자료 접근 주소. PostgreSQL 연결 문자열이 아님

서버 전용:

- `DATABASE_URL`: Vercel·Neon 연결에서 자동 등록. 표 소유자 역할 필요
- `NEON_AUTH_BASE_URL`: Neon 인증 주소. Vercel 연결에서 자동 등록
- `SERVER_APP_ORIGIN=https://hanan-moa.vercel.app`
- `OPENAI_API_KEY`: Vercel 비밀 환경변수. **VITE_ 접두어 금지**
- `OPENAI_MODEL`: 사용할 실제 모델 이름. 키와 모델 둘 다 있어야 사용 가능
- 선택: `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`

연결 문자열·키는 저장소, 문서, 브라우저 코드에 넣지 않는다. 운영 환경에만 비밀값을 연결하고 시험 배포와 공유하지 않는다. 비밀 환경변수는 명령줄로 내려받아도 빈 값일 수 있으며, 값이 없다고 운영 연결을 덮어쓰지 않는다.

## 데이터베이스와 승인

적용 파일: `neon/migrations/202610220001_cloud_ai.sql`

공개 스키마:

- `moa_forms`: 사용자별 양식과 삭제 표시
- `moa_chat_drafts`: 사용자별 화면 대화 초안
- `moa_ai_chats`: 서버 인공지능 대화·현재 양식
- `moa_aggregations`: 사용자별 취합 기록 요약 (내 업무공간 취합 이력). 결과 엑셀·받은 파일은 저장하지 않음

비공개 스키마:

- `moa_allowed_users`: 허용 이메일·사용자 ID·활성 여부
- `moa_ai_usage`: UTC 날짜별 호출 수
- `moa_ai_leases`: 중복 실행 잠금

표 6개 모두 행 수준 보안 사용. 양식·초안은 승인된 본인 행만 읽고 쓴다. 서버 대화는 본인 조회만 허용하며 서버가 저장한다. 비공개 표와 사용량 함수는 브라우저에서 실행 불가. Neon 기본 사용자 ID는 UUID이므로 모든 사용자 외래키와 호출 함수 인자를 UUID로 맞춘다.

첫 승인 계정: `ksw1727@gmail.com`. 실제 Neon 사용자 ID에 고정하며 이메일 인증도 별도로 필요하다. 운영 담당자는 Neon 관리 화면에서 사용자 생성 후 해당 계정을 승인 목록에 등록한다. 승인 목록 변경 전에는 대상 계정을 확인받는다. 임의로 모든 계정을 허용하거나 도메인 전체를 승인하지 않는다.

Neon 인증 설정의 이메일 회원가입은 꺼 두고, 이메일 로그인·인증은 유지한다. 인증 서비스의 다른 가입 경로가 있더라도 서버와 자료 접근 정책에서 허용목록을 다시 확인한다. 신뢰 도메인은 실제 운영 주소만 등록한다. Google 등 외부 로그인은 현재 앱에서 제공하지 않는다.

## 보안·비용 제한

- 서버는 JWT 서명·발급자·수신자·만료·UUID·이메일 인증 상태를 검증하고 DB 현재 계정·차단·허용목록도 재확인
- 비밀키는 OpenAI의 한난MOA 전용 서비스 계정, 운영 서버에만 저장. 가능하면 응답 생성 권한만 허용
- 인공지능 요청 한도: 관리자 페이지에서 정함(기본 무제한, 관리자는 따로 정하지 않으면 무제한). 동시 사용자 요청 1개
- 사용량 제한은 DB 원자적 함수로 적용. DB 또는 승인 확인이 실패하면 인공지능 호출하지 않음
- 요청당 최초 호출과 수정 호출을 합쳐 최대 3번. 출력 상한 8,000토큰, 요청 처리 시간 55초
- 일일 횟수는 **금액 한도와 다름**. OpenAI 요금·잔액·자동 충전 설정은 관리자가 별도로 관리
- 서버용 키에는 만료 기한이 없으므로 운영자가 정기 교체하고 유출 시 즉시 폐기해야 함. 비밀값을 문서나 대화에 옮기지 않음
- 첨부 요약 최대 5개·각 12,000자, 요청 전체 240KB. 더 큰 양식은 조용히 잘라 보내지 않고 안내
- 브라우저 사용자별 캐시는 암호화가 아님. 공용 컴퓨터에서는 별도 브라우저 프로필 또는 사용 후 사이트 데이터 삭제 권장
- 양식·대화 충돌은 자동 덮어쓰기 하지 않음. 다른 기기의 최신 자료는 다시 불러오거나 재로그인하여 확인
- 이메일 인증·비밀번호 재설정·로그인 코드는 서로 다른 용도. 코드는 로그·문서에 남기지 않음

## 배포와 확인

1. 별도 브랜치에서 작업하고 `main` 직접 변경·커밋·푸시 금지
2. `node node_modules/vitest/vitest.mjs run`, `npm run build`, `git diff --check`
3. 새 Neon DB에만 SQL을 트랜잭션으로 적용하고 권한 확인. 실패하면 전부 롤백
4. Neon 자료 접근 캐시 갱신, 인증 신뢰 도메인 등록
5. Vercel 새 프로젝트에 환경변수 등록 후 운영 배포
6. 로그인·인증 메일·계정 승인·양식 저장/재접속·대화 저장·인공지능 생성·엑셀 내보내기 실제 확인
7. 비로그인 API 거절 및 다른 사용자 자료 거절 확인. 사용자 키·DB 연결값이 웹 산출물에 없는지 확인

2026-10-22 작업은 커밋·푸시 없이 로컬 작업 브랜치를 명령줄 배포한 상태다. 저장소의 기본 브랜치와 자동 배포 연결은 별도 검토·병합 후 설정한다. Supabase 초안은 `docs/archive/supabase-cloud-draft/`에만 보관하며 실제 Supabase에는 적용하지 않았다.

- 추가된 사람은 로그인 화면에서 [로그인 코드 받기]로 들어온다. 처음이면 [이메일 인증 코드 받기]가 먼저 필요할 수 있다
- 적용 SQL: `neon/migrations/202610220002_admin.sql` (적용 완료)

## AI 사용 한도 (2026-10-22 추가)

- 관리자 페이지 [AI 사용 한도]: 전체 하루 한도, 사용자 기본 하루 한도. 비우면 무제한
- 사용자 목록의 [하루 한도]: 사용자별 한도. 비우면 기본 한도를 따르고, 0이면 AI 사용 불가
- 관리자는 사용자별 한도를 따로 정하지 않으면 전체·기본 한도 모두 적용하지 않음(무제한)
- 하루 = UTC 기준(한국 시간 오전 9시 초기화). 요청 1번 = 1회, 한도 판단은 DB 함수 `moa_private.moa_ai_reserve(user, chat, lease)`가 잠금 안에서 처리
- 적용 SQL: `neon/migrations/202610220003_ai_limits.sql` (적용 완료). 이전 환경변수 `AI_DAILY_USER_LIMIT`·`AI_DAILY_GLOBAL_LIMIT`는 쓰지 않음

## 내 업무공간 (2026-10-22 추가)

- 첫 화면 [내 업무공간] 탭. 양식을 만든 날 → 양식의 제출 기한을 달력 막대로, 취합 기다리는 양식, 내가 만든 양식, 취합 이력을 보여준다
- 누가 냈는지는 취합해야 알 수 있으므로, 취합 전 양식에는 날짜와 제출처 수만 보인다
- 취합을 마치면(결과 파일 내려받기) 요약만 남긴다: 양식·버전·제출 수·안 낸 곳·모은 줄·확인한 칸·검산. 이 기기에 먼저 쓰고 `moa_aggregations`에 올린다. 못 올린 기록은 업무공간을 열 때 다시 올린다
- 적용 SQL: `neon/migrations/202610220004_aggregations.sql` (2026-10-22 적용 완료, 자료 접근 캐시 갱신 요청함). 표가 없으면 서버에서 불러오지 못했다는 안내와 함께 이 기기 기록만 보인다
