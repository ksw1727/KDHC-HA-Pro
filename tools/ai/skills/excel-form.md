# 엑셀 양식 스킬 (한난MOA용)

Anthropic xlsx 스킬의 원칙 중 **양식을 만들고 읽는 데 필요한 것만** 한난MOA 규칙으로 옮겼다.
엑셀 파일은 프로그램이 만든다. 너는 `form.json`만 정확하게 만들면 된다.

## 1. 요구를 글자 그대로 따른다
- 사용자가 말한 **항목 이름·순서·선택지·단위를 그대로** 쓴다. "성명"이라고 하면 "이름"으로 바꾸지 않는다.
- 사용자가 말하지 않은 항목을 덧붙이지 않는다. 꼭 필요해 보이면 만든 뒤 "○○도 넣을까요?"라고 묻는다.
- 사용자가 말한 계산은 그 계산 그대로 `calc` 칸으로 만든다. 더 "좋은" 계산으로 바꾸지 않는다.
- 시작 양식(`moa new`)에 들어 있던 자리표시 항목(예: "이름", "1행", "항목 1")은 요구에 없으면 지운다.

## 2. 항목마다 알맞은 칸 종류를 고른다
| 받는 값 | type | 서식 |
|---|---|---|
| 금액 | number | `thousands: true`, `unit: '원'`(천원·백만원이면 그 단위), `min: 0` |
| 인원·개수 | number | `decimals: 0`, `unit: '명'`/`'개'`/`'건'`, `min: 0` |
| 비율 | number | `unit: '%'`, `decimals` 1, `min: 0`, `max: 100` |
| 날짜 | date | `dateFormat: 'yyyy-mm-dd'`, 연·월만이면 `'yyyy-mm'` |
| 정해진 보기 | select | 사용자가 말한 보기를 그대로 `options`에 |
| 휴대폰·전화·이메일·사업자번호 | pattern | `'mobile'`·`'phone'`·`'email'`·`'bizno'` |
| 긴 설명·비고 | memo | |
| 다른 칸으로 계산되는 값 | calc | `formula` (필수 아님) |

- 숫자는 숫자 칸으로 받는다. "3명"처럼 글자로 받으면 합계를 못 낸다. 단위는 `unit`에 둔다.
- 연도(2026)는 숫자 계산에 쓰지 않으면 `select`나 `text`로 둔다.
- 합계·소계는 입력받지 않고 계산한다 (목록·혼합형은 `calc`, 표형은 `totalRow`·`totalCol`).

## 3. 입력하는 사람을 돕는다
- 꼭 받아야 하는 칸만 `required: true`(노란 칸). 모든 칸을 필수로 만들지 않는다.
- 헷갈릴 칸에는 `help`로 짧은 안내를 단다 (예: "1인당 금액, 원 단위", "없으면 0").
- 목록형·혼합형에서 적는 법이 헷갈리면 `exampleRow`로 실제 같은 예시 한 줄을 넣는다.
- 제목(`title`)에는 무엇을 모으는지, `guide`에는 기한·주의를 쓴다. 사용자가 말한 기한은 `deadline`, 문의처는 `contact`에도 넣는다.

## 4. 쓰던 엑셀 읽기
`./moa read-excel` 결과는 칸마다 값·서식·수식을 보여 준다. 이렇게 읽는다.
- **입력 칸 찾기**: 비어 있고 `채움`(특히 노란색 #FFF5D1 계열)·`빈 칸(테두리만)`·`잠금 해제`인 칸이 입력 칸. 노란 채움은 필수로 본다.
- **머리글**: 굵게·채움이 있는 줄. 머리글 끝의 `*`는 필수 표시이니 이름에서 빼고 `required: true`로 옮긴다.
- **반복 줄**: 같은 모양 줄이 여러 번 이어지면 목록(`list`)이다. 몇 줄인지가 `maxRows`.
- **한 번만 적는 칸**: 목록 위의 "담당자·연락처" 같은 칸은 혼합형의 `fields`.
- **병합된 제목·안내 줄**: 1·2행 병합 문장은 `title`·`guide`로 옮긴다 (입력 칸이 아니다).
- **수식**: `=D10*C10` 같은 수식과 메모의 `계산: [인원] × [교육비]`는 `calc`의 `formula`로 옮긴다. 원래 수식과 같은 뜻인지 확인한다.
- **입력 규칙**: `textLength 10~13`(연락처) → `pattern`, `whole 0~1000000` → number `min`·`max`로 옮긴다.
- **원본의 관례가 우선이다.** 원본의 이름·순서·보기·필수 표시를 그대로 살린다. 더 깔끔하게 고치지 않는다.

## 5. "검사 통과"는 끝이 아니다
`moa check` 통과는 **규칙에 맞다**는 뜻이지 **요구대로 만들었다**는 뜻이 아니다 (xlsx 스킬: 오류 없는 수식도 틀린 칸을 가리킬 수 있다).
`moa preview`를 보고 사용자 요구의 항목을 하나씩 짚어 본다.
- 말한 항목이 모두 있고 이름이 같은가? 말하지 않은 항목은 없는가?
- 숫자 칸은 숫자, 날짜 칸은 날짜인가? 계산 칸은 맞는 칸들을 쓰는가?
- 제출처가 요구대로인가 (어디가, 몇 곳, 무엇이라 부르는지)?
틀린 곳이 있으면 고치고 다시 `check` → `preview` 한다.

## 6. 가정은 숨기지 않는다
요구에 없던 것을 정했으면(제출처, 줄 수, 단위 등) 답에 "○○로 해 두었어요"라고 **모두** 적는다.
