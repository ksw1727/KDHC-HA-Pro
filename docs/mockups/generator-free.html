3. 검사 규칙 (제안)

취합 방식가능한 조건안 될 때 안내 (예)
같은 틀 시트 ① 입력 줄 영역은 0~1개
② 줄 영역 아래에는 입력 칸·글자 칸이 없음 (늘어나는 줄이 덮어씀)
③ 줄 영역이 없으면 입력 칸 자리는 "(지사별 시트 참고)"로 두고, 값은 지사별 펼치기 시트에 지사마다 한 줄로 모음 (이때 지사별 펼치기는 자동 필수)
④ 숫자 표는 여러 개 가능 (칸끼리 더함)		 "입력 줄 영역이 2개예요. 취합본 한 장에 줄을 이어 붙일 곳이 하나여야 해요 → 하나로 합치거나 하나를 숫자 표로"
"취합하면 '점검 내역' 줄이 늘어나 아래 B12 '확인자'를 덮어써요 → 줄 영역 위로 옮기세요"
지사별 펼치기입력 줄 영역이 없음 (입력 칸·숫자 표만)"입력 줄 영역은 지사마다 줄 수가 달라 옆으로 펼칠 수 없어요"
시트 모으기항상 가능—
제출 현황표⑤ 제출처를 식별함(목록 있음·지사명 입력)"제출처 식별을 '식별 안 함'으로 두면 누가 냈는지 셀 수 없어요"
공통 (모든 방식)입력 영역끼리 겹치지 않음 · 입력 칸·줄 칸에 이름이 있음 · 같은 이름 없음 · 입력 영역은 합친 칸이 아님 · 입력 영역이 1개 이상"B4와 B8:D13 영역이 겹쳐요" · "이름 없는 입력 칸 D4 → 이름을 정해 주세요(취합본 머리글이 돼요)"

4. 어떻게 취합 파트와 이어지나 (개발자용)

  • 새 구조 ID layout: 'free'. 사용자가 지정한 영역은 기존 블록으로 그대로 저장: 입력 칸 → fields, 입력 줄 영역 → list, 숫자 표 → matrix. 여기에 블록마다 놓인 자리와 글자 칸·병합·열 너비(schema.free)만 더합니다.
  • 엑셀 안 셀 지도(CellMap)는 지금과 똑같은 모양 → 취합 파트의 값 읽기·검산은 거의 그대로 씁니다.
  • 검사 규칙은 공통 계약 src/contract/free.ts(freeAggregationChecks)에 두어 생성·취합 파트가 같이 씁니다. 줄 영역이 있으면 혼합형 규칙, 없으면 입력 칸은 지사별 시트로 모입니다.
  • 공통 계약 변경이므로 개발자 2 승인이 필요합니다.
